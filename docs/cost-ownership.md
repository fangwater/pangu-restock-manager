# 采购与物流成本归属

成本台账及模板由备货系统维护，财务系统通过只读接口读取。旧 SHEIN PNL 库存单数据保留为移交前档案，旧页面入口跳转到备货系统，旧库存成本 API 停止对外提供写入。

入口：`/pangu-restock/?view=costs`、`/pangu-restock/?view=cost-templates`。

## 数据与维护

新增 SQLite 表：`cost_tickets`、`cost_templates`、`cost_history`、`cost_migrations`。库存单及模板包含各自的 SKU/费用明细和分类/费用类型，金额使用十进制字符串存储及 Decimal 计算。历史费用保存自己的币种，已有记录的费用类型禁止删除或修改币种/计算方式。库存单及未使用模板支持软删除，修改采用版本号保护并记入审计表。

迁移保留原库存单、SKU 行和费用记录 ID、单号、金额、备注及原创建/更新时间。完整源导出和 SHA256 同时保存在 `cost_migrations`。首次移交以事务执行；相同导出再次执行不重复导入，不同导出禁止覆盖移交后修改。

采购币种已于 2026-10-26 经业务确认是 CNY，历史空白采购币种已补齐，新单默认选择 CNY；可在页面选择其他支持的币种。原库存单没有成本生效日期，仍保留空白，可在新页面维护。单号年月和创建/更新时间不能替代成本生效日期。原来未填写的费用继续为空，保持与明确录入零金额的区别。

采购币种和费用分类币种使用下拉选择，选项为 CNY、USD、EUR、HKD。旧 RMB 币种统一为 CNY，原始迁移档案保持不变。海运费用按各费用分类记录独立币种；历史“海运费用RMB”的 3 笔费用仍保留 CNY，未按名称批量重标为 USD。

## 接口

- `GET /api/costs`：当前台账、模板、分币种汇总及迁移信息；不含各单完整明细。
- `GET /api/costs/tickets/{id}`：单据明细及最近修改记录。
- `GET /api/costs/export`：版本 1 完整成本快照，`owner=pangu-restock-manager`，供财务读取。
- `PUT /api/costs/tickets`、`PUT /api/costs/templates`：新增或修改，需传 `version`，新建为 0。
- `POST /api/costs/tickets/remove`、`POST /api/costs/templates/remove`：按 ID 与版本号软删除。
- 所有写入沿用备货系统的同源及 `X-Pangu-Request: restock` 校验。
- 财务增加 `GET /api/profit/costs`，通过 `RESTOCK_API_BASE_URL`（默认本机 18110）读取完整成本快照；上游失败返回不可用，不返回虚构的空成本。

成本原始台账通过 FIFO、费用分摊及汇率配置参与订单毛利核算，不能直接用采购总额抵减某月销售回款。期初、日期、费用和有效汇率缺失时继续保留待核对。

## 迁移操作与回退

1. 用 SQLite backup API 备份当前备货库，保存原代码和财务二进制。
2. 使用 `scripts/export-legacy-costs.sql` 只读导出原数据库，先在备货库副本中验证迁移及原有数据。
3. 通过 `deploy/legacy-cost-transfer.conf` 停止旧库存成本 API 并跳转旧入口，再读取最终源导出。
4. 使用 `python3 transfer_costs.py --input <导出 JSON> --database <备货 SQLite>` 完成一次移交，核对所有原始记录及分币种金额。
5. 发布备货维护页面及财务只读接入，验证旧入口跳转、备货数据和财务快照一致。

回退时先暂停新成本写入并导出移交后的修改，再恢复备货代码/数据库、财务二进制和旧 Nginx 配置。不要在已产生新修改后直接恢复旧成本写入，避免两个来源分别积累数据。


## 2026-10-28 费用人工核对接入

财务维护独立的未归因账单核对记录，按申报金额或人工原币金额关联同店订单 / SKU，原始账单不回写。备货毛利引擎接收生效核对分摊及版本证据；来源或商品依据变化的记录保留未归因，不回落到原 SKU 直接匹配。已确认非订单款项只计入费用日期所在期间的非订单净额，缺少日期或汇率继续保留缺口，不计入 SKU 毛利。核对记录及版本随计算明细进入核算快照；历史快照不受后续核对变更影响。采购、头程、物流成本仍由备货系统管理，币种及历史人民币海运费用不变。


## 2026-10-28 采购 CSV 批量维护

采购台账支持按当前单号 / SKU、模板和费用条件导出全部采购行与附加费用，超过列表分页的数据一并导出。UTF-8 CSV 包含单号、版本、模板及模板版本、采购币种、生效日期、单据备注和 SKU / 费用明细；费用类型表按现有模板导出，币种沿用 CNY/USD/EUR/HKD 配置，不通过费用名称推断。

导入先预览，再用服务端生成的修订 SHA256 保存。预览使用只读事务；修订绑定 CSV 文本、来源凭证、采购单、模板及关联入库记录，相关数据变化后必须重新预览。单号新建使用版本 0；更新须提供当前版本。完全相同的内容可跳过旧版本并且不增加版本或审计记录。所有新增 / 更新在同一事务内完成，任何错误整批回滚。

导入按单号和仓库 SKU / 费用类型合并，不删除文件中未出现的明细，不允许切换已有单的模板。文件中出现的行以行内容为准：空白金额和单价表示未录入，数值 0 表示已知零；采购金额为空且有单价时按数量乘单价计算，计量费用按数量乘单价计算。所有金额使用 Decimal 精确计算，超过现有十位小数精度时拒绝，不静默舍入。导入不生成或确认入库；采购单版本变化后，原入库批次仍按既有规则待核对。

每次实际变更保存 CSV 文本、来源凭证、修订及文件文本 SHA256，并在单据审计中保存变更前后及导入依据。导入页显示最近 20 次记录，可查看逐项变更或导出明细；导出使用电子表格文本转义，金额精度和业务标识保持不变。SHA256 对去掉 UTF-8 BOM 的上传文本计算；再次导出的列顺序、BOM 和文本转义可能不同，不作为原始文件字节副本。

接口：

- `GET /api/costs/tickets/export.csv?q=&template=&fee=`：按筛选导出全量明细；`template_only=1` 下载空模板，`catalog=1` 导出费用类型。
- `POST /api/costs/tickets/import/preview`：`csv` 与 `reference`，返回单据、逐项变化、关联入库数及 `revision`。
- `POST /api/costs/tickets/import`：同一内容、凭证及 `revision`，成功返回批次 ID 和新增 / 更新 / 跳过数。
- `GET /api/costs/tickets/imports`、`GET /api/costs/tickets/imports/{id}`：历史及只读变更明细；`?export=1` 导出该次导入明细。

导入上限为 700 KB CSV、5000 行、200 张库存单，写请求仍受全站 1 MB JSON 和同源 / `X-Pangu-Request: restock` 约束。原始旧系统移交档案及历史人民币海运费用不因上线而改写。
