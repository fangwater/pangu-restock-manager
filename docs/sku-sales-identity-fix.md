# 销售 SKU 与仓库需求分离

2026-10-12 修复：原快照先按仓库 SKU 聚合订单 quantity，导致被映射的不同包装规格混入同一销量。版本 3 同时保留销售 SKU、仓库 SKU、换算系数，报表独立聚合两个数量。

Panda Homes，2026-09-12 至 2026-10-11，粉色衣架原始订单核对：

| 销售 SKU | 订单销量 | 仓库 SKU | 系数 | 仓库需求 |
| --- | ---: | --- | ---: | ---: |
| VH+H-50Pcs-Pink-45cm | 561 | VH+H-50Pcs-Pink-45cm | 1 | 561 |
| VH+H-100Pcs-Pink-45cm | 64 | VH+H-50Pcs-Pink-45cm | 2 | 128 |

50Pcs 行的销量为 561，仓库需求为 689；100Pcs 行的销量为 64，该店对应 100Pcs 仓库需求为 0。原 625 是两个销售 SKU 数量混加，不能作为 50Pcs 自身销量或仓库需求。

- 销量占比、排名、趋势和同期对比按销售 SKU 原始订单件数计算。
- 采购建议、库存覆盖与自动店铺分配按仓库需求计算。多个 SKU 映射到同一仓库 SKU 时逐项相加，避免源 SKU 重复采购。
- 页面按店铺同时显示销量和仓库需求，详情展示来源 SKU、订单数量、换算系数；其他仓库承接的需求单列。
- Excel 增加「仓库需求明细」，保存计划保留其当次明细。移除跨商品混算的单一“销量换算系数”。
- 锁定计划不自动修改；旧快照暂停建议并等待版本 3 同步。
- 订单日期、状态和退款处理沿用既有规则，此次不修改日期归属。

验证：26 项 Python 测试通过；Go 全套 `go test -race ./...` 在隔离 PostgreSQL 通过；浏览器验证 561/689、64×2=128、跨 SKU 去向、按 689:100 店铺需求分配，以及桌面/移动布局；Excel 数值单元格与明细数量通过自动核对。
